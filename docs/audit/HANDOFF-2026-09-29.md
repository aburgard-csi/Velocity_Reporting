classification defined once so that cannot happen again. This branch is the first phase: the

## What the branch contains, by commit

1. `odd_rows.odd_member / open_odd / odd_source / extract_odd` — ONE rule for which .csv inside
   an ODDD zip is the ODD. Ten files had their own; they disagreed. Guard: `tests/test_odd_source.py`.
2. `odd_rows.flag_yes / has_debit / is_eligible / is_business / is_personal / business_class /
   latest_elig_col` — ONE reading of the Debit? / Business? / Elig columns (Yes in any case;
   a blank Business? is neither). Nine files compared to literals. Guard: `tests/test_odd_predicates.py`.
3. `build/ars_pipeline/engine/` — v5's `core/`, `monthly_analysis/` (minus ICS, deposits),
   `transaction_intelligence/`, `workbook.py`, `guarantee.py`, `text/`, `config/` as one package.
   Reads debit/business/Reg E through `odd_rows` (`rege_state`). Writes no slide.
   Guard: `tests/test_engine_imports.py`.
4. `engine_config.py` — the engine's client record from Aaron's `Inputs/ARS Settings/
   ars_code_tables.json` + the workbook's Key Assumptions (interchange rate, NSF fee). No
   v5 `clients_config.json`. Missing tables → stages skipped with warnings, never zeros.
5. `run_analysis.py` — runs the engine on the ODD the build already reads and on
   `Inputs/Txn Files/<id>/` (zipped, via `rpe_env.open_txn`); evidence to
   `Build Artifacts/analysis/<period>/<id>/` (metrics.json, txn_metrics.json,
   enriched.parquet, report.md, tables, manifest). Test: `tests/test_run_analysis.py`.
6. Reconciliation — the ODD's own `Elig` flag is the eligibility of record on both sides;
   under `RPE_ANALYSIS=1` `build_ars_gen.py` runs the engine after the James block and STOPS
   the build if eligible base / eligible personal / personal take rate differ from
   metrics_gen and the pack (`run_analysis.reconcile`). Reg E and responders are reported,
   not compared (bases differ by design). Test: `tests/test_engine_reconciliation.py`.
7. Guards: no month literal in the engine; structural zero is None. `tests/test_engine_guards.py`.
8. Nine Transaction Intelligence slides under `RPE_ANALYSIS_SLIDES=1` (`ti_slides.py`,
   `ti_charts.py`), before "Reg E Review", source notes, tiles in the figure sidecar.
   Test: `tests/test_ti_slides.py` (ends with the golden chain, both flags on).
9. CHANGELOG entry, CLAUDE.md file-map rows, ars-deck agent note.

## Rules to keep while working in his repo

- Every classification rule lives once, in `odd_rows.py`; the guard tests fail on a second copy.
- Fix the builder, never a delivered deck. Build from the template shell, never from a client deck.
- Missing data is stated, never zeroed; slides are never dropped silently.
- Every slide has a source note; every figure goes through the sidecar.
- Any change that moves a number, its source, a claim or a render gets a CHANGELOG entry
  (newest first, dated, with the reason and the test).
- No new dependency pins (the build machine gets no new installs without Aaron).
- Commit messages are a behaviour sentence, `TEST:` prefix on this branch, name the test.
