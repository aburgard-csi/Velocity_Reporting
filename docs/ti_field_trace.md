# Transaction file field trace

Generated by `scripts/ti_field_trace.py` from the code. Do not edit by hand: run `python scripts/ti_field_trace.py` to rebuild it (and `docs/ti_field_trace.json` beside it). `tests/test_ti_field_trace.py` fails when either file is stale.

Each transaction field is followed from the loader (`ti/transaction_intelligence/loader.py`) through the analyses that read it (`ti/transaction_intelligence/*.py`, run by `ti/txn_sections.py`) to the pack keys they write and the slides (`ti/deck/txn_*.py`, titled in `ti/chapters_txn.py`) that draw those keys. The trace is static (Python's `ast`) and follows data flow: a key lists the fields its value was computed from, row filters included. It does not follow `if` tests, so a field used only to decide whether a key is written is not listed against that key; and within one function a reused name carries every field it was ever bound to, so a key can list a field that only shares a name with its inputs. Anything the scan cannot resolve is listed under Unresolved, never dropped.
