Before you start

There is nothing to install. You need:

  • The CSM_Reporting folder open in File Explorer: \\PADMIS105\Velocity_company\CSM_Reporting. Connect to the VPN first if you are off site.
  • The client number, for example 1441.
  • About 650 MB free on your PC the first time. The launcher sets up its own copy of Python there, which takes a few minutes, once.
Close the client's deck in PowerPoint before you build. A new build replaces the deck in Outputs, and it can't do that while the file is open.

Build a deck

  1. 1

    Double-click Build ARS Deck.bat

    It's in the CSM_Reporting folder. If Windows asks whether to run a file from the network, choose Run. You don't need to run it as administrator.

    Prefer a browser? Double-click ARS Deck Builder.bat instead. It opens the same checks and build in your browser, with a list of clients to pick from and each step shown as it runs. Keep its black window open while you build, and close it when you're done.

  2. 2

    Type the client number and press Enter

    It checks the client and this month's data before building anything:

    ARS deck status: client 1441, period 2026.09 [ok] 1441 FNB Alaska (CSM: James Gilmore) [ok] clients.md: ARS, MM workbook [ok] ODD extract: in Inputs (2026-09-03) [ok] ARS workbook: in Inputs (2026-09-03) [ok] DCO: in Inputs (2026-09-14) Ready to build. Build the ARS deck and put it in Outputs [Y,N]?
  3. 3

    Press Y to build

    A build takes 3 to 15 minutes. It names each step as it goes, so you can see it working:

    Building (this takes 3 to 15 minutes)... [..] Reading the ARS workbook (0 min) [..] Reading the ODD extract (1 min) [..] Computing the ODD metrics (2 min) [..] Drawing the charts (3 min) [..] Assembling the deck (4 min) [..] Validating the deck (9 min) [ok] Validation: 0 FAIL, 28 REVIEW [ok] In Outputs: ...\Outputs\James Gilmore\1441-2026.09-ARS-FNB Alaska ARS Results.pptx Done. The deck is in Outputs, ready to review, save as PDF and email.

    "REVIEW" items are normal notes from the quality check. Only a FAIL stops a deck.

  4. 4

    Press any key to close the window

    Then go to your folder in Outputs. See After it builds.

What the checks mean

MarkMeaningWhat to do
[ok]This check passed.Nothing.
[!!]A warning. The build can still run.Read it. A missing DCO, for example, leaves the DCO's eligible accounts blank.
[built]This month's deck is already in Outputs.It asks whether to rebuild it and replace the one in Outputs. Say Y only if something changed, such as a formatting fix or a corrected input.
[STOP]The deck can't be built yet. The line says why.See the table below.

After it builds

  1. Open the deck in Outputs\<your name>\ and review it.
  2. Save it as a PDF and email it to the client as usual.
If a slide looks wrong, don't fix it by hand in PowerPoint. Tell Aaron what's wrong so the build is fixed and every client's deck gets the correction.

Any older deck for the same client and month is moved to Outputs\_Archive\. Nothing is deleted.

If something goes wrong

The first run sits on "Setting up Python on this PC"

That's normal the first time, and after Aaron releases an update. It takes a few minutes, once.

"The deck built clean but could not be put in Outputs"

The client's deck in Outputs is open, probably in PowerPoint. Close it and run Build ARS Deck.bat again.

"The build stopped at ..." or "POSSIBLE DATA ISSUE"

The client's data has a problem the deck can't work around, such as account status codes that aren't mapped. These are usually corrected on the client's code sheet. Send Aaron the client number and the build.log path the window shows.

"Validation: 1 FAIL" (or more)

The deck didn't pass the quality check, so it wasn't put in Outputs. Send Aaron the client number.

"The launcher runtime is missing"

The launcher isn't fully installed on the share. Ask Aaron to run the launcher release.

Inputs\The ODD extracts and workbooks the build reads. Leave these alone.
