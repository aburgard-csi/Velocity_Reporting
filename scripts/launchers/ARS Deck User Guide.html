ARS Deck User Guide

How a client's monthly ARS Executive Review is built, what data it needs and where that data lives, how to build one yourself with CSM Sheila or Build ARS Deck CLI, and what each field and term in the deck means.

Before you start

There is nothing to install. You need:

  • The CSM_Reporting folder open in File Explorer: \\PADMIS105\Velocity_company\CSM_Reporting. Connect to the VPN first if you are off site.
  • The client number, for example 1441.
  • About 650 MB free on your PC the first time. The launcher sets up its own copy of Python there, which takes a few minutes, once.
Close the client's deck in PowerPoint before you build. A new build replaces the deck in Outputs, and it can't do that while the file is open.

How a deck is built

One client, one month, one deck. Everything on a slide comes from the client's own data files, and the same steps run for every client.

  1. 1 Check the client and the data
  2. 2 Read the workbook and DCO
  3. 3 Read the ODD extract
  4. 4 Compute the metrics
  5. 5 Draw the charts
  6. 6 Assemble the slides
  7. 7 Validate
  8. 8 File in Outputs
StepWhat happens
1. CheckThe client must be on the Client CSM List, have ARS on its product list, be listed for ARS in the roster, and have this month's ODD extract and ARS workbook in Inputs. A problem here is a [STOP] and nothing is built. See What the checks mean.
2. Workbook and DCOThe ARS workbook supplies the program's financials (revenue, costs, profit, profitability), the mailings and their response, the Lift Matrix and the trend in debit spend. The DCO supplies the client's debit card distribution by swipe tier.
3. ODD extractThe ODD is read straight out of its zip, one account per row. Its codes are sorted into the standard categories listed in the data dictionary. A value that maps to none of them is flagged and never guessed.
4. MetricsAbout a hundred figures are computed from the accounts: product mix, take rates, swipe tiers, mailing response, Reg E, before and after activity, new account profile. Comparisons use the last complete month only.
5. ChartsEach chart is drawn at the size of its slide box, in the house palette and fonts.
6. AssembleThe slides are filled in from the ARS template, never from another client's deck. The cover, agenda, Summit slide, Questions and Contact are added, and the Contact card is the client's CSM. Every slide's speaker notes name its data source.
7. ValidateA quality check reads the finished file for banned wording, text that overflows, figures that disagree with their data, another client's name left behind, and whether the file is sound. Any FAIL stops the deck. "REVIEW" items are notes.
8. FileA clean deck goes to Outputs\<CSM>\ named <client>-<yyyy.mm>-ARS-<Client> ARS Results.pptx. An older deck for the same client and month moves to that folder's _Archive\.

What is in the ARS deck

The slide set is the same for every client. A slide is never dropped because its data is thin; it says what the extract doesn't carry instead.

SectionSlides
ProgramProduct Mix & ARS Eligibility, Excluded Accounts, Program Overview, ARS Financial Performance, and Revenue Guarantee on any deck whose profitability is below 3 : 1.
Debit usageMonthly Summary (last 12 months), Debit Usage Segmentation by Swipe Tier, Average Ticket by Swipe Segment.
MailingsMailing Insights, Mailing Response Summary and Ranking by Tier, the response and movement slides for the latest mailer, Transaction Increase Over the Ask, Sustained Respondent Activity, and Responder Activity before vs after.
Debit card review12-month eligible take rate for personal, business and by branch; Overall Debit Swipes & Spend; NSF/OD Activity Over Time.
Reg E reviewOpt-in for all personal accounts, for accounts opened in the last 12 months, by branch and by account vintage.
Key TakeawaysThe summary slide that closes the main deck.
AppendixBranch Reference, program reach and repeat responders, responder age and balance profile, the new account profile slides, account growth, retention by tenure and first-year closure.

Four rules shape every slide:

  • Missing data is stated, not zeroed. If the extract doesn't carry a field, the slide says so.
  • Comparisons use complete months only. A month the extract covers only in part is left out, and the slide says it was left out.
  • Movement is worded from the figures. Within 2% is "almost flat". A rise is stated with its numbers. A fall is described as not having an impact on that measure.
  • No slide is edited by hand. A wrong slide is fixed in the build, so every client's deck gets the fix.

Build a deck

  1. 1

    Double-click Build ARS Deck CLI.bat

    It's in the CSM_Reporting folder. If Windows asks whether to run a file from the network, choose Run. You don't need to run it as administrator.

    Prefer a browser? Double-click ARS Deck Builder GUI.bat instead — the same checks and the same build, with a client list to pick from, the Lift Matrix and each client's data issues. See CSM Sheila in your browser.

  2. 2

    Type the client number and press Enter

    It checks the client and this month's data before building anything:

    ARS deck status: client 1441, period 2026.10 [ok] 1441 FNB Alaska (CSM: James Gilmore) [ok] clients.md: ARS, MM workbook [ok] ODD extract: in Inputs (2026-10-02) [ok] ARS workbook: in Inputs (2026-10-02) [ok] DCO: in Inputs (2026-10-01) Ready to build. Build the ARS deck and put it in Outputs [Y,N]?
  3. 3

    Press Y to build

    A build takes 3 to 15 minutes. It names each step as it goes, so you can see it working:

    Building (this takes 3 to 15 minutes)... [..] Reading the ARS workbook (0 min) [..] Reading the ODD extract (1 min) [..] Computing the ODD metrics (2 min) [..] Drawing the charts (3 min) [..] Assembling the deck (4 min) [..] Validating the deck (9 min) [ok] Validation: 0 FAIL, 28 REVIEW [ok] In Outputs: ...\Outputs\James Gilmore\1441-2026.10-ARS-FNB Alaska ARS Results.pptx Done. The deck is in Outputs, ready to review, save as PDF and email.

    "REVIEW" items are normal notes from the quality check. Only a FAIL stops a deck.

  4. 4

    Press any key to close the window

    Then go to your folder in Outputs. See After it builds.

CSM Sheila in your browser

Double-click ARS Deck Builder GUI.bat in the CSM_Reporting folder. A black window opens and your browser follows a few seconds later. Keep the black window open while you work — it is the program itself — and close it when you are done. Sheila runs the same checks and the same build as Build ARS Deck CLI.bat; she just shows you more while you decide.

Tabs across the top: Decks, Lift Matrix, Data Issues and Slide Review. The What's new list beside them is the last few changes to the build, and Change log opens the full record.

The cycle, in the top right corner

The pill in the corner is the month you are working in. It is the calendar month, so it moves to the new month on the 1st on its own. For a normal build you never touch it.

Click it to look at an earlier cycle. Pick a month and the whole page answers for that month: who already has a deck, what a build would read, which clients are still waiting on data. A build you start while an earlier month is picked builds that month. Your pick holds until you choose the current month again or reload the page, so glance at the pill before you build.

Decks

Every client with a deck to build, grouped by CSM, with a box to filter by name or number. A client's row carries a tag when there is something to know:

Tag on the rowMeaning
In Outputs 2026.10This cycle's deck is already built and sitting in your Outputs folder.
BuildingThat client is building right now.
Queued #2Waiting its turn. Builds run one at a time and each starts on its own.
Error 2026.10The last build did not reach Outputs. Open the client — the steps say where it stopped — and its button reads Retry build.
Lift Matrix expiredThe workbook's Lift Matrix window has run out, so the deck would price this month at an out-of-date matrix. Bradford reloads it; the Lift Matrix tab is where the replacement comes from.

Click a client to see its checks — the same [ok], [!!] and [STOP] lines as the window version, explained under What the checks mean — then Build. When another of the client's programs has its data this cycle you get two buttons: Build ARS only, or Build combined with every program that has data named on it. A program left out is named with the reason.

Under those checks, an ARS client's page has a Transaction Intelligence panel and an ARS Companion panel. Each is a separate presentation from the Executive Review, with its own checks and its own build button. Their decks go to Outputs beside the Executive Review and never replace it; the list shows them as TI in Outputs and Companion in Outputs.

A client's checks are kept for a few minutes so the page stays quick. A row that says it is checking again holds its Build buttons until the fresh answer arrives; Check again always re-reads the share from scratch.

Lift Matrix

Each ARS client's current Lift Matrix, out of their workbook, beside a new one calculated from their own ODD — side by side, with the change and each segment's step. The interchange rate, NSF/OD fee, collection rate and outlier cap are yours to change: edit them and press Recalculate. Until you do, the figures below still belong to the previous values and the export is held, so a matrix is never exported at rates it was not calculated at.

Export this matrix downloads the Excel file for Bradford and records that you exported it. It is never written to Outputs, and it changes nothing in the client's workbook — Bradford loads it.

The matrix a deck prices from is the one in the client's workbook. Exporting a new one here is a request to Bradford, not a change to this month's deck.

Data Issues

What is wrong with a client's data, in one place: the items from the ODD and Workbook Issues and CSM Data Gaps pages, plus the code and Lift Matrix checks from the morning refresh. Each item is dated, and the chips along the top filter them — Blockers, Decisions, Gaps, Warnings, Codes and Lift Matrix, Completed — each with its count.

When you have dealt with one, press Mark complete and it leaves the open list. It stays out until a newer ARS, MRPCPM or ICS workbook lands for that client, which is when the item is worth a second look.

Unmapped product, Reg E and account status codes are corrected on the client's code sheet, never forced in the build. Every client page links their newest sheet: Open code sheet opens it, Show it in File Explorer shows you where it lives.

Slide Review

Vote Keep, Delete or Appendix on each slide, and star the ones you like best. Votes are for the program's template, not for any one client, so you can use it beside any deck. The slide list is the build itself — the same slides for every client — so it appears at once.

The row of links under every client

Wherever a client appears, the same row sits under their name — Deck checks, Lift Matrix, N data issues, Open code sheet, Show it in File Explorer — minus the tab you are already on. One client, three views, without going looking for them.

Data feeds

An ARS deck reads six things. Four are files that arrive each month; two are lists that say who the client is and who owns them.

What an ARS deck needs

Copied into Inputs\ODDD at 08:00.[STOP] The file has no month in its name and is replaced in place, so Sheila reads the pull date stamped inside it. An earlier month's extract counts as missing.

Three smaller inputs are filled in for you: the client's product, Reg E and status code tables (Inputs\ARS Settings), branch names (Inputs\Branch Names, from the Charts workbooks and the referral data; branch charts show names when most of a client's branch numbers resolve, numbers otherwise), and the client's logo (Inputs\Logos\<id>.png). A missing logo never fails a build.

A file being in Inputs is not the same as it being this month's file. The ODD zip keeps the same name every month, so the build trusts the pull date stamped inside it, or the source share, never the file name alone.

How files get into Inputs

A scheduled check, RPE Source Watch, runs once a day at 08:00 on Aaron's machine. It looks at this month's and last month's folders on both shares, and copies anything new into the right Inputs folder by kind. It also files the weekly reports and ICS workbooks that arrive by email. It needs the VPN; off the VPN it does nothing and leaves yesterday's files alone. Nothing is deleted from the shares.

The shares are the original copies. If a file in Inputs is ever wrong or missing, it can be fetched again from where it came from.

Data dictionary

The ODD extract has several hundred columns. These are the ones the ARS deck reads, and what the build does with each.

The ODD extract

Standard categories

The build sorts the wording each core uses into one fixed set of categories, the same for every client. Any value that doesn't map is flagged and the build asks before going on.

FieldCategoriesNotes
Reg E opt-in statusReg E Opt In, Reg E Opt Out, Reg E DefaultOpt in covers Yes, Accepted and Opted In. Opt out covers No, Declined and Revoked. Default covers no response, failed to respond and no decision. A blank, Ineligible or Exempt account is not applicable and is left out of the percentages.
Account statusOpen, Closed, Dormant, Inactive, Frozen, Charged Off, OtherPurge at Yearend and Pending Closeout are Closed. New This Cycle and Pending Activation are Open. Manually controlled is Other, on purpose.
Status code (used only when the words are blank)O and A are Open. C is Closed. X is Charged Off.Some cores fill the code and leave the words blank on every account that isn't open. A blank status with no usable code is Other.
Account typePersonal, Business, OtherFrom Business?, as above.
If a code or wording maps to none of these, the build reports a possible data issue. It never picks a category for you. The fix is on the client's code sheet.

The ARS workbook

The deck reads these tabs by name, and finds each figure by its row label. A workbook that has never been calculated reads as one month, no mailings and $0, so the build stops on it instead.

TabWhat the deck takes from it
Executive Financials MMThe client name, the data month, months and mailings to date, total incremental revenue, costs and profit — for the month and for the program to date.
All Months Rollup MMThe month-by-month revenue series.
Key Trends MMDebit spend and card-holding accounts by month. A blank month stops the build rather than reading as $0.
Mail Response Summary MMEach mailing and its response.
Lift Matrix MMThe Lift Matrix, with its Start Date and End Date. The data month must fall inside that window.
DCO MMCard-holding accounts and their spend by swipe tier.
Actuals MMThe program's P&L, line by line. This feeds ARS Financial Performance and Revenue Guarantee.

MM and SM are two revenue models, not working and broken. An MM workbook prices revenue from the Lift Matrix in the "MM" tabs. An older SM workbook splits revenue into interchange and NSF on the individual mailing tabs, and its "MM" tabs are empty on purpose. The build reads the right tabs for each, and an SM client has no Lift Matrix slide. The roster records which one a client is.

Terms on the slides

TermWhat it means in the deck
CycleThe calendar month a deck is for. Its name uses that month, for example 2026.10.
Complete monthA month whose data was pulled after it ended and isn't far below its usual level. Every year-over-year and latest-month figure uses the last complete month, and a month left out is named on the slide.
Eligible accountAn account the ARS program can reach: Elig is Yes in the latest month.
Take rateThe share of eligible accounts that hold a debit card. The 12-month charts look at eligible personal or business accounts opened in the last 12 months, by branch.

Swipe tierAn account's monthly swipes in bands: Non-User (none), 1–5, 6–10, 11–15, 16–20, 21–25 and 26 Plus.

ResponderAn account whose Resp carries one of the five response codes for a mailing.

After it builds

  1. Open the deck in Outputs\<your name>\ and review it.
  2. Save it as a PDF and email it to the client as usual.
If a slide looks wrong, don't fix it by hand in PowerPoint. Tell Aaron what's wrong so the build is fixed and every client's deck gets the correction.

Any older deck for the same client and month is moved to the _Archive\ folder inside your own Outputs folder. Nothing is deleted.

To check where a figure came from, open the slide's speaker notes. Every slide names its source file or dashboard and the period behind its numbers.

If something goes wrong

"Copying the launcher code to this PC" appears

That happens on a first run and after each new release, and takes up to a minute. After that the launcher runs from a copy on your PC, which is much faster than running from the share.

The first run sits on "Setting up Python on this PC"

That's normal the first time, and after Aaron releases an update. It takes a few minutes, once.

"The deck built clean but could not be put in Outputs"

The client's deck in Outputs is open, probably in PowerPoint. Close it and run Build ARS Deck CLI.bat again.

"The build stopped at ..." or "POSSIBLE DATA ISSUE"

The client's data has a problem the deck can't work around, such as account status codes that aren't mapped, or a blank month in the workbook's Key Trends. Codes are usually corrected on the client's code sheet. Send Aaron the client number and the build.log path the window shows.

"Validation: 1 FAIL" (or more)

The deck didn't pass the quality check, so it wasn't put in Outputs. Send Aaron the client number.

The data is on the share but the build says it isn't

The share is copied into Inputs once a day, at 08:00, and only when the VPN is on. Ask Aaron to copy it now, or check that you are connected.

"The launcher runtime is missing"

The launcher isn't fully installed on the share. Ask Aaron to run the launcher release.

Questions or a build that won't finish: contact Aaron Burgard with the client number. Guide updated 2026-10-29.
