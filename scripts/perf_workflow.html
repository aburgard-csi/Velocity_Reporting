How an Executive Review gets made

From a file landing on a CSI share to a deck recorded as sent: what runs, what it reads, what it writes, and what stops a deck from shipping. Everything lives under one pipeline root, \\PADMIS105\Velocity_company\CSM_Reporting, which needs the VPN off-site.

The cycle

ARS, ICS and MRPC ship one deck per client per month. CashPlease runs weekly and always uses the newest weekly workbook.

  1. As the data team lands files

    Data lands at the source

    ODD extracts go to each CSM's own folder on the company share. DCOs, ARS workbooks and MRPCPM analyses go to the client-reports share, filed by account manager. The MRPC and CashPlease weeklies and the ICS workbooks arrive by email. ICS and MRPC client sheets are pulled from the VIP dashboards.

    SourcesVelocity_company\<CSM>\…ODDD (five CSM folders)
    Velocity_clientreports\<yyyy.mm>\<Account Manager>
    Mailbox: Bradford Sanders (MRPC, CashPlease), Matt Milliman (ICS)
  2. Daily 08:00 · "RPE Source Watch" · watchdog at 08:15

    Copied into Inputs

    The watch compares this month's and last month's source folders to what it saw yesterday, reads the mailbox, and copies each new or re-landed file into its folder under Inputs/, for every client except those clients.md marks as stopped. It keeps only the newest version of each file, and never overwrites a workbook that was opened and re-saved locally. Off the VPN it stops and saves nothing.

    Runsscripts/watch_sources.py
    WritesInputs/<kind>/, Build Artifacts/source_watch_latest.md
  3. Monthly per client · CashPlease weekly

    Each program's deck is built

    A builder fills its program's stripped template shell from the data, never from another client's deck. ARS runs the ODD optimizer first to turn a 400 MB extract into a compact data pack. Who gets which program comes from clients.md, never from which files happen to exist.

    Runsscripts/build_month.py, scripts/build_cashplease.py
    ReadsInputs/, templates/*_template.pptx, clients.md
  4. For a client on two or more programs

    Program decks become one Executive Review

    Each program deck passes its own gate first, then they are assembled into a single deck with one title, agenda, Q&A and contact slide. The ARS Appendix stays with ARS.

    Runsbuild/assemble_combined.py
    Section orderARS · ICS · MRPC · CP
  5. Every deck, before it ships

    The validation gate

    A non-zero exit blocks delivery. The fix is in the builder, then a rebuild, never a hand-edit of the deck. Nothing in the gate proves a deck opens and renders correctly, so open one deck before a batch goes to clients.

    Runsvalidation/validate_deck.py, validation/qa_all.py
    Checksunit suite, text fit and autofit, claims against their figures, reference-client leaks, source notes, package integrity
  6. When the gate passes

    Saved to Outputs

    Finished decks only, as .pptx and never PDF, in a folder per CSM, Outputs/<CSM name>/, named by client, period and program. Anything a build writes to prove itself goes to Build Artifacts/. Superseded decks move to Outputs/Archive/.

    WritesOutputs/<CSM name>/<id>-<yyyy.mm>-<PROGRAM>-….pptx
  7. When the deck reaches the client · page refresh daily 08:30

    Recorded as sent

    A deck in Outputs/ proves it was built, not that it was sent. Sending is recorded by hand with Mark sent, on this page or on the local delivery dashboard. The 08:30 refresh folds the page's records into the delivery log and republishes the performance page when its figures change.

    WritesBuild Artifacts/deliveries.json
    Runsscripts/refresh_performance_dashboard.py

What stops a deck

Each rule exists because its absence once shipped a wrong deck that looked right.

  • A program not in clients.mdLeftover files are not a signal. A cancelled program's data stays on disk and must not rebuild its section.
  • An input from the wrong monthA stale ODD extract, or an ICS workbook older than the deck, would validate cleanly and report the wrong month.
  • A value the pipeline cannot mapAn unmapped Reg E or account status is flagged and asked about before building, never guessed.
  • A text swap that matched nothingThe slide would keep the template's placeholder figures and look plausible, so the ARS build fails instead.
  • A slide without its sourceEvery slide's notes name the source file, pull date and selection for this client, never the template's client.
  • A claim its figures contradictA change within ±2% is described as almost flat, and "rose" over a decline fails the gate.
  • Missing data shown as zeroThe deck says the data isn't in this extract. It never renders 0%, an empty chart, or drops the slide.
  • A package that will not openDuplicate or orphaned slide parts pass every text rule. Only the package check reads the file directly.
